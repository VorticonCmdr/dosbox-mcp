dosbox-mcp

Quick start Configuration Tools Ghidra pairing GitHub ↗

dosbox-mcp is an MCP server that connects any MCP-capable agent runtime to a running dosbox-automation instance — typing into DOS programs, reading the screen, capturing frames and video, running sandboxed Lua, inspecting memory, driving a full headless debugger. This page is a developer-facing map of every tool this bridge actually registers right now, generated straight from the tool definitions in dosbox_mcp/tools/*.py — not a pitch.

This repo is VorticonCmdr's fork of upstream dosbox-automation/dosbox-mcp, adding the debugger, Ghidra address-mapping, symbols, batch, and wait_for tool groups documented below; it drops upstream's mixer tools. It's built against VorticonCmdr's dosbox-automation fork, not upstream's dosbox-automation — most of the tools here need REST routes upstream doesn't have. For this fork's code, the repo; for the wire contract, PROTOCOL.md.

Quick start

Point an MCP client at a running (or spawnable) emulator.

# 1. enable the API on a running dosbox-automation instance
dosbox --set webserver_enabled=true

# 2. add the bridge to your MCP client (Claude Code)
claude mcp add dosbox -- uvx --from vorticoncmdr-dosbox-mcp dosbox-mcp

# or a JSON MCP config:
# { "mcpServers": { "dosbox": { "command": "uvx", "args": ["--from", "vorticoncmdr-dosbox-mcp", "dosbox-mcp"] } } }
# pipx install vorticoncmdr-dosbox-mcp / pip install vorticoncmdr-dosbox-mcp work too
# (published under this name to avoid colliding with upstream's own "dosbox-mcp" package)

# 3. that's it - the bridge finds the running emulator, checks what it
#    can do, and registers the matching tools
#    ask your agent for bridge_status, or bridge_start to spawn one itself

Pairs with Ghidra for reverse engineering

The Debugger tools (execution control: pause/step/continue and breakpoints) plus Ghidra address mapping and Symbols let an agent combine this bridge with a separate Ghidra MCP server: analyze a program statically in Ghidra, then set breakpoints and interpret a paused CPU state against the exact same addresses live in DOSBox.

Address mapping is pure arithmetic

debug_map_set_base and friends never talk to Ghidra or the engine — they translate addresses once anchored at one known correspondence point (usually the entry point). Exact for .COM programs and single-segment .EXE programs.

The .COM 0x100 offset

Ghidra's real-mode loader can't rebase a .COM import to a segment:0x0100 layout, so it typically lands at 0000:0000 — a constant 0x100 below every live address. Anchoring absorbs that automatically.

Symbols follow you everywhere

Once loaded via debug_symbols_load, a symbol field appears on disassembly, debugger stop records, backtrace frames, and the DOS memory map.
